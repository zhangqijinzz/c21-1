# LatencyLab

本地前端请求链路预算实验室。这里的推演是可重复的时间估算，不会调用真实接口。

## 本地运行

- 运行时：Node.js `>=20 <21`
- 安装依赖：`npm ci`
- 开发预览：`npm run dev`
- 质量门：`npm run lint`、`npm run test`、`npm run typecheck`、`npm run build`

## 功能模块

1. 链路项目：新建、改名、切换与复制项目。
2. 请求编排：增删节点、设置依赖及耗时、超时、重试、失败和降级参数；依赖变成环时拒绝连线。
3. 链路分段：把节点按评审口径归入有名称、有先后顺序的分段（如首屏、可交互、次要内容）；分段重名、节点未归属、分段顺序与依赖方向矛盾都会给出明确结果。
4. 时序推演：乐观、预期、保守三种波动假设；不限并发或设置并发上限；展示各分段完成时间、整条链路的分段构成、完成预算、排队等待和关键链路，并标出拖后腿的分段。
5. 方案对比：保存当前图、分段和计算结果，比较两份参数快照（含分段完成时间）并恢复任一快照。
6. 本地项目区：管理、复制和删除项目，查看保存状态。

## 兼容

早于链路分段功能保存的老数据（项目与快照均无 `segments`、节点无 `segmentId`、快照无 `segmentStats`）可照常打开、推演和对比：缺失字段按“无分段 / 未归属”处理，不会被当成损坏数据；老快照对比时会用保存的图重新推演补齐分段统计。

## 架构

`views` 只渲染状态并转发事件。功能 VM 将项目、节点、推演和方案用例分开编排；纯规则位于 `shared/domain`；Repository 依赖 IndexedDB Service，并写入版本化 localStorage 恢复副本。项目数据不会发到服务器。

默认示例：分段按“首屏 → 可交互 → 次要内容”排列。会话校验和功能开关并发启动（首屏）；资料与目录在会话后开始（可交互）；个性推荐等待功能开关和资料（次要内容）。结果使用确定性预算：延迟波动取所选情境、超时截断单次耗时、失败概率决定重试次数期望，重试退避按 200ms 指数增长并封顶 2 秒。降级耗时按最终失败概率加权。并发上限使用稳定拓扑顺序做资源排队估算。

分段完成时间取段内最后一个节点完成的时刻；“拖后腿”分段为关键链路上累计耗时最长的分段。等待条与关键链路高亮在时间线中按分段成组显示，可直接看出排队与瓶颈落在哪一段。
