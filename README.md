# LatencyLab

本地前端请求链路预算实验室。这里的推演是可重复的时间估算，不会调用真实接口。

## 本地运行

- 运行时：Node.js `>=20 <21`
- 安装依赖：`npm ci`
- 开发预览：`npm run dev`
- 质量门：`npm run lint`、`npm run test`、`npm run typecheck`、`npm run build`

## 功能模块

1. 链路项目：新建、改名、切换与复制项目。
2. 请求编排：增删节点、设置依赖及耗时、超时、重试、失败和降级参数；依赖变成环时拒绝连线。可创建链路分段（如首屏、可交互、次要内容），调整分段顺序并把节点归属到分段。
3. 时序推演：乐观、预期、保守三种波动假设；不限并发或设置并发上限；展示完成预算、排队等待和关键链路。启用分段后给出各分段的完成时间与瓶颈分段，时间线按分段成组。
4. 方案对比：保存当前图和计算结果（含分段构成与各分段完成时间），比较两份参数快照并恢复任一快照。
5. 本地项目区：管理、复制和删除项目，查看保存状态。

## 架构

`views` 只渲染状态并转发事件。功能 VM 将项目、节点、分段、推演和方案用例分开编排；纯规则位于 `shared/domain`；Repository 依赖 IndexedDB Service，并写入版本化 localStorage 恢复副本。项目数据不会发到服务器。

默认示例：会话校验和功能开关并发启动；资料与目录在会话后开始；个性推荐等待功能开关和资料。结果使用确定性预算：延迟波动取所选情境、超时截断单次耗时、失败概率决定重试次数期望，重试退避按 200ms 指数增长并封顶 2 秒。降级耗时按最终失败概率加权。并发上限使用稳定拓扑顺序做资源排队估算。

## 链路分段规则

- 分段只有名称和先后顺序；节点通过 `stageId` 归属，未归属的节点在推演时归入「未分段」组并给出提示。
- 分段重名或名称为空属于配置错误，会阻断推演，需先改名。
- 分段顺序与依赖方向矛盾（靠前分段的节点依赖靠后分段）时给出警告，推演仍按拓扑顺序进行。
- 老版本保存的项目与快照没有分段字段，打开时按空分段处理，不视为损坏，可照常推演、对比与恢复。
